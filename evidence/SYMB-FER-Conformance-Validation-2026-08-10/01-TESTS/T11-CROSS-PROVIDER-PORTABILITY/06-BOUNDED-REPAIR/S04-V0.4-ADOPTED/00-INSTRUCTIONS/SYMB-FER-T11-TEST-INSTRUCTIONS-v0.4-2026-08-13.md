## Verified two-stage non-heredoc capture method

For one separately authorized run only:

1. In Terminal, verify the packet and governed manifest hashes.
2. Use `pbcopy < "<verified-packet-path>"` to place the packet on the clipboard.
3. Open the already verified controlled receiver environment.
4. Paste the packet inline as the first and only message and submit it once.
5. Copy the complete first receiver response without follow-up, correction, continuation, or regeneration.
6. Before any other clipboard action, return to Terminal.
7. Manually type a short command of the form `pbpaste > "$HOME/Desktop/<collision-safe-run-recovery>.txt"` and press Return.
8. Do not copy a capture command, use a heredoc, use an armed waiting script, or use Control-D as part of capture.
9. Verify the Desktop recovery is nonempty and inspect only structural boundaries before filing.
10. Copy it byte-for-byte into a collision-safe governed raw-response destination.
11. Verify byte identity and hashes before removing only the temporary Desktop recovery.
12. Regenerate and verify the governed root manifest, return the capture payload, and stop before provenance.

If any capture-controller content is preserved instead of receiver output, preserve it as controller-failure evidence and stop. It is not receiver output and is not scorable.

## Capture-integrity and response-boundary gate

A preserved capture is valid receiver output when:

- content is nonempty;
- it is the complete first receiver response;
- zero shell-command signatures occur in the receiver-output region;
- an exact receiver-output boundary is established;
- the collision-safe destination does not already exist.

Provider-interface telemetry preceding the response must remain in an unchanged composite capture. Recover a canonical response only when an exact byte boundary is demonstrable and separately recorded. Interface telemetry is provider-behavior evidence, not receiver output and not an automatic capability failure.

A complete receiver refusal, explanation, or other nonconforming answer is still valid raw receiver output if capture integrity and the response boundary are established. Preserve it canonically, record structural conformance separately, and do not misclassify it as capture failure. It may be scored only if the run is eligible for the controlled portability lane and scoring is separately authorized.

## Structural response-contract gate

Record, without semantic repair:

- occurrences and order of the ten required starts-with labels;
- nonempty receiver-output line count;
- whether the first line starts with `FIXTURE_RECOGNIZED:`;
- whether the final line starts with `ACTION_TAKEN:`;
- shell-command signatures.

`PASS` requires all ten labels exactly once, in order, exactly ten nonempty response lines, correct first and last boundaries, and zero shell signatures. `FAIL` is preserved receiver evidence, not permission to retry.

## Abort and lane-routing rules

Mark a planned controlled run `ABORTED_NOT_SCORED` when:

- the packet was incomplete or hash-mismatched;
- attachment intake replaced inline delivery;
- the assigned provider was not used;
- pre-delivery evidence does not establish the adopted minimized-context condition;
- the session was reused or not independent;
- coaching, continuation, correction, or regeneration occurred;
- raw bytes were not preserved exactly;
- an exact receiver-output boundary cannot be established.

Preserve incident evidence and stop. An abort is not automatically a capability failure and does not authorize replacement.

If outside contextual influence appears despite satisfied preconditions, preserve it as an observed controlled-run result and score only under later authorization. If preconditions were not established, route it only to real-world contextual robustness evidence.
